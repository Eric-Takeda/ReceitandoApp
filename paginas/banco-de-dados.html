1. Banco de Dados

O Receitando utiliza o Supabase como plataforma de backend. Os dados estruturados são armazenados em um banco de dados PostgreSQL, que permite organizar as informações em tabelas e estabelecer relacionamentos entre elas.

O banco de dados é utilizado para armazenar informações das receitas, ingredientes, categorias, perfis e favoritos dos usuários.

2. Principais tabelas

As tabelas organizam os dados utilizados pelas diferentes funcionalidades do aplicativo.

2.1. profiles

Armazena informações complementares dos usuários autenticados.

  • id: identificador do usuário.
  • nome: nome do usuário.
  • email: endereço de e-mail.
  • foto_url: endereço da imagem do perfil.
  • data_criacao: data de criação do registro.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

2.2. receitas

Armazena as informações principais de cada receita.

  • id: identificador da receita.
  • user_id: identificador do usuário.
  • titulo: nome da receita.
  • descricao: descrição da receita.
  • modo_preparo: instruções de preparo.
  • tempo_preparo: tempo necessário para preparar.
  • porcoes: quantidade de porções.
  • imagem_url: endereço da imagem da receita.
  • data_criacao: data de criação da receita.
  • data_atualizacao: data de atualização da receita.
  • publica: define se a receita criada é visível para todos.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

2.3. ingredientes

Armazena os ingredientes associados às receitas, incluindo seus nomes, quantidades e unidades de medida, conforme as colunas existentes.

  • id: identificador do ingrediente.
  • receita_id: identificador da receita.
  • nome: nome da receita.
  • quantidade: quantidade numérica da receita.
  • unidade: unidade de medida da receita.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

2.4. categorias

Armazena as categorias utilizadas para organizar as receitas, como massas, carnes, sobremesas, saladas e bebidas.

  • id: identificador da categoria.
  • nome: nome da categoria.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

2.5. receita_categorias

Estabelece a relação entre receitas e categorias. Essa tabela permite associar receitas às categorias correspondentes.

  • receita_id: identificador da receita.
  • categoria_id: identificador da categoria.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

2.6. favoritos

Registra as receitas favoritedas pelos usuários, permitindo recuperar a lista de favoritos de cada conta.

  • id: identificador do registro.
  • user_id: identificador do usuário.
  • receita_id: identificador da receita.
  • data_criacao: data em que a receita foi favoritada.

3. Relacionamentos entre tabelas

As tabelas são relacionadas por identificadores e chaves estrangeiras. Esses relacionamentos permitem associar os ingredientes, as categorias e os favoritos às receitas e aos respectivos usuários.

  • Receitas e ingredientes: relacionam uma receita aos seus ingredientes.
  • Receitas e categorias: utilizam a tabela receita_categorias para estabelecer a associação entre receitas e categorias.
  • Usuários e favoritos: permitem identificar quais receitas foram salvas por cada usuário.
  • Usuários e perfis: associam as informações complementares do perfil à conta correspondente.

A configuração exata das chaves primárias, chaves estrangeiras e restrições deve ser consultada no esquema do banco de dados.

4. Armazenamento de imagens

O Supabase Storage é utilizado para armazenar arquivos de imagem, evitando que os arquivos binários precisem ser gravados diretamente nas tabelas do banco de dados.

4.1. profile-images

Bucket destinado às imagens de perfil dos usuários.

4.2. recipe-images

Bucket destinado às imagens das receitas.

Os endereços das imagens podem ser armazenados nos registros correspondentes e utilizados pelo aplicativo para exibir os arquivos.

5. Segurança e permissões

O acesso aos dados deve respeitar as permissões configuradas no Supabase. As políticas de Row Level Security (RLS) permitem definir quais registros podem ser consultados ou modificados por cada usuário.

As permissões de armazenamento também devem controlar o envio, a leitura, a atualização e a exclusão de imagens, conforme as regras estabelecidas para cada bucket.

6. Considerações finais

A utilização do PostgreSQL e do Supabase permite centralizar os dados do aplicativo, organizar os relacionamentos entre as informações e disponibilizar serviços de autenticação e armazenamento de arquivos.

A estrutura documentada deve corresponder às tabelas, colunas e políticas efetivamente configuradas no projeto.
