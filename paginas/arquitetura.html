1. Arquitetura do Sistema

A arquitetura do Receitando é composta pelo aplicativo desenvolvido em Flutter, pela lógica implementada em Dart e pelos serviços de backend disponibilizados pelo Supabase.

Essa organização permite separar a interface apresentada ao usuário dos serviços responsáveis pela autenticação, persistência dos dados e armazenamento de imagens.

2. Organização do Projeto

Os arquivos do aplicativo são organizados em diretórios e arquivos Dart, que contêm as telas, os componentes visuais e a lógica necessária para executar as funcionalidades.

A pasta lib é o principal diretório do código Dart do aplicativo Flutter.

3. Arquivo principal

main.dart

O arquivo main.dart é o ponto de entrada do aplicativo Flutter. Ele é responsável por iniciar a aplicação e configurar os elementos necessários para seu funcionamento.

Neste projeto, esse arquivo também realiza a inicialização do Supabase, serviço utilizado para autenticação de usuários, acesso ao banco de dados e gerenciamento de arquivos.

Após a inicialização, o aplicativo apresenta a tela inicial definida na configuração do projeto, permitindo que o usuário comece a navegar pelo sistema.

4. Organização das telas e componentes

As telas e os componentes do aplicativo estão organizados no diretório lib/. As páginas ficam na pasta pages/, enquanto o arquivo principal e outros componentes de controle permanecem diretamente no diretório lib/.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

4.1. Autenticação e acesso

  • LoginPage: permite que o usuário acesse sua conta.
  • CadastroPage: permite criar uma nova conta no aplicativo.
  • RecuperarSenhaPage: permite solicitar a recuperação da senha por e-mail.
  • NovaSenhaPage: permite definir uma nova senha durante o processo de recuperação.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

4.2. Navegação e gerenciamento de receitas

  • HomePage: apresenta o menu principal e as opções de navegação do aplicativo.
  • ReceitasPage: apresenta a lista de receitas, a pesquisa e os filtros por categoria.
  • DetalheReceitaPage: apresenta as informações detalhadas de uma receita.
  • CriarReceitaPage: permite cadastrar receitas próprias.
  • EditarReceitaPage: permite alterar informações das receitas que o usuário tem autorização para editar.
  • FavoritosPage: apresenta as receitas salvas como favoritas.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

4.3. Perfil e informações do aplicativo

  • PerfilPage: apresenta e permite gerenciar as informações do perfil do usuário.
  • ConfiguracoesPage: reúne as opções de configuração disponíveis no aplicativo.
  • SobrePage: apresenta informações sobre o aplicativo.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

4.4. Controle de tema

ThemeController: arquivo responsável por gerenciar o tema visual do aplicativo, permitindo utilizar o modo claro, o modo escuro ou acompanhar o tema definido no sistema operacional.

5. Comunicação com o Supabase

O aplicativo utiliza a biblioteca supabase_flutter para se comunicar com os serviços do Supabase. Por meio dessa integração, as telas podem consultar, cadastrar, atualizar e excluir dados, conforme as permissões configuradas.

O Supabase Auth é utilizado para gerenciar a autenticação dos usuários. O banco de dados PostgreSQL armazena as informações estruturadas, enquanto o Storage é utilizado para guardar arquivos de imagem.

6. Fluxo de funcionamento

De maneira geral, o funcionamento do aplicativo segue este fluxo:

  1. O aplicativo é inicializado.
  2. O usuário acessa a tela de autenticação.
  3. Após o login, o menu principal é apresentado.
  4. O usuário acessa as funcionalidades disponíveis.
  5. Quando necessário, o aplicativo consulta ou modifica os dados no Supabase.
  6. Os resultados são apresentados na interface.

7. Considerações sobre a arquitetura

A organização do código em diferentes arquivos facilita a manutenção, a identificação de erros e a evolução das funcionalidades.

A comunicação com o backend e as permissões de acesso devem respeitar as configurações de segurança do Supabase.
